# 用户操作手册

适用对象：行政、HR、普通业务用户。

本文档以当前代码中的页面、菜单和接口为准。截图位置均为占位符，后续内部试用稳定后再补充真实截图。

## 系统简介

宿舍与通勤管理系统当前用于美国本地内部试用，覆盖以下已实现范围：

- 宿舍管理
- 房间管理
- 人员管理
- 签证与停留管理
- 入住分配
- 车辆基础档案管理

当前系统不包含司机管理、派车调度、接送需求、路线优化。

> 截图占位符：系统首页 / Dashboard

## 登录

登录地址：

```text
http://服务器IP:8000/ui/login
```

如果已经登录，也可以访问：

```text
http://服务器IP:8000/ui/
```

系统使用用户名和密码登录。用户名不区分大小写，例如 `admin`、`Admin`、`ADMIN` 会被视为同一个账号。

忘记密码处理流程：

1. 联系系统管理员或 IT。
2. 管理员进入“用户管理”页面。
3. 选择对应用户并填写“重置密码”。
4. 用户使用新密码重新登录。

当前没有自助找回密码、邮件验证码或短信验证码功能。

## Dashboard

Dashboard 展示当前宿舍、人员停留、入住和车辆的汇总状态。

统计卡片含义：

| 卡片 | 含义 |
| --- | --- |
| 宿舍总数 | 当前未删除的宿舍数量 |
| 房间总数 | 当前未删除的房间数量 |
| 总床位数 | 当前未删除房间的床位数合计 |
| 当前入住人数 | 状态为 `active` 的入住记录数量 |
| 空床数 | 总床位数减去当前入住人数 |
| 入住率 | 当前入住人数 / 总床位数 |
| 风险人数(<=60天) | 停留风险中 red 与 yellow 人数合计 |
| Red 风险人数 | 最大停留日期已过期或 30 天内到期的人数 |
| Yellow 风险人数 | 最大停留日期 31 到 60 天内到期的人数 |
| Green 正常人数 | 最大停留日期超过 60 天的人数 |
| Unknown 未维护人数 | 未维护最大停留日期或未维护停留信息的人数 |
| 可用车辆数 | 状态为 `available` 的车辆数量 |
| 维修车辆数 | 状态为 `maintenance` 的车辆数量 |
| 停用车辆数 | 状态为 `disabled` 的车辆数量 |
| 30天内保险到期车辆数 | 保险到期日不为空且在未来 30 天内或已到期的车辆数量 |
| 30天内年检到期车辆数 | 年检到期日不为空且在未来 30 天内或已到期的车辆数量 |
| 30天内保养到期车辆数 | 保养到期日不为空且在未来 30 天内或已到期的车辆数量 |

Dashboard 下方还显示：

- 未来 30 天最大停留到期
- 未来 60 天最大停留到期
- 已超期未离美

点击停留风险相关卡片会进入“停留风险”页面。

## 宿舍管理

菜单：`宿舍`

用于维护宿舍基础档案。普通用户可以新增和修改宿舍；删除按钮仅 admin 可见。

操作说明：

1. 填写宿舍字段。
2. 点击“新增宿舍”保存。
3. 点击列表中的“修改”可回填表单并编辑。
4. admin 点击“删除”前会出现二次确认。

字段说明：

| 字段名 | 含义 | 是否必填 |
| --- | --- | --- |
| 名称 | 宿舍名称 | 是 |
| 类型 | 宿舍类型，来自字典 `dormTypes` | 是 |
| 地址 | 宿舍地址 | 是 |
| 租期开始日期 | 宿舍租赁开始日期 | 否 |
| 租期结束日期 | 宿舍租赁结束日期 | 否 |
| 状态 | 宿舍状态，来自字典 `statuses` | 是 |

列表字段：ID、名称、类型、地址、租期开始、租期结束、状态、操作。

删除校验：

- 如果宿舍下属房间存在 `active` 入住记录，系统会阻止删除。
- 删除宿舍采用软删除；关联未删除房间也会被标记为已删除。

> 截图占位符：宿舍管理页面

## 房间管理

菜单：`房间`

用于维护宿舍下的房间与床位信息。普通用户可以新增和修改房间；删除按钮仅 admin 可见。

字段说明：

| 字段名 | 含义 | 是否必填 |
| --- | --- | --- |
| 宿舍 | 房间所属宿舍 | 是 |
| 房间名 | 房间名称或编号 | 是 |
| 房间类型 | 房间类型，来自字典 `roomTypes` | 是 |
| 床位数 | 房间可入住人数上限，必须大于 0 | 是 |
| 性别限制 | `Any` 不限制，`Male` 仅男性，`Female` 仅女性 | 否 |
| 状态 | 房间状态，来自字典 `statuses` | 是 |

列表字段：ID、宿舍、房间名、类型、床位、性别限制、状态、操作。

系统校验：

- 入住时房间必须属于选择的宿舍。
- 入住时房间床位不能已满。
- 入住时人员性别必须符合房间性别限制。
- 状态为 `disabled` 的房间不能办理入住。
- 如果房间存在 `active` 入住记录，admin 删除时会被阻止。

> 截图占位符：房间管理页面

## 人员管理

菜单：`人员`

用于维护人员主数据，并可同步维护该人员的签证与停留信息。

人员字段说明：

| 字段名 | 含义 | 是否必填 |
| --- | --- | --- |
| 中文名 | 人员中文姓名 | 是 |
| 英文名 | 人员英文名，可为空 | 否 |
| 部门 | 人员所属部门，来自字典 `departments` | 是 |
| 人员类型 | 人员类型，来自字典 `personTypes` | 是 |
| 性别 | `Male` 或 `Female` | 是 |

签证与停留字段说明：

| 字段名 | 含义 | 是否必填 |
| --- | --- | --- |
| 签证类型 | 签证类型，来自字典 `visaTypes` | 条件必填 |
| 赴美日期 | 到达美国日期 | 条件必填 |
| 计划离美日期 | 计划离开美国日期 | 条件必填 |
| 最大停留日期 | 合规允许的最晚停留日期 | 否 |
| 实际离美日期 | 实际离开美国日期 | 否 |
| 备注 | 停留说明 | 否 |

条件必填说明：

- 新增或编辑人员时，可以只维护基础人员信息，不填写签证与停留。
- 一旦填写任意签证与停留字段，则签证类型、赴美日期、计划离美日期必须同时填写。

列表字段：中文名、英文名、部门、类型、性别、停留风险、当前住宿状态、操作。

人员状态说明：

- 当前住宿状态来自入住分配记录。
- 有 `active` 入住记录显示“在住”。
- 没有 `active` 入住记录显示“未入住”。

删除校验：

- admin 才能删除人员。
- 如果人员存在 `active` 入住记录，系统会阻止删除。
- 删除人员采用软删除，并会软删除其停留信息。

## 停留风险

菜单：`停留风险`

该页面不是普通主数据页，而是签证与停留风险清单页。页面按风险类型分组展示人员停留状态，并允许快速编辑停留信息。

风险颜色含义：

| 风险 | 页面显示 | 含义 |
| --- | --- | --- |
| red | 红色标签 / `red` | 最大停留日期已超期，或剩余合法停留天数小于等于 30 天 |
| yellow | 黄色标签 / `yellow` | 剩余合法停留天数为 31 到 60 天 |
| green | 绿色标签 / `green` | 剩余合法停留天数大于 60 天 |
| unknown | 灰色标签 / `未维护` | 未维护最大停留日期或未维护停留信息 |

页面分组：

- 已超期
- 30天内到期
- 60天内到期
- 未维护最大停留日期

字段说明：

| 字段名 | 含义 | 是否必填 |
| --- | --- | --- |
| 人员 | 要维护停留信息的人员 | 是 |
| 签证类型 | 签证类型，来自字典 `visaTypes` | 是 |
| 赴美日期 | 到达美国日期 | 是 |
| 计划离美日期 | 计划离开美国日期 | 是 |
| 最大停留日期 | 合规允许的最晚停留日期 | 否 |
| 实际离美日期 | 实际离开美国日期 | 否 |
| 备注 | 停留说明 | 否 |

admin 可删除停留记录；普通用户可新增和修改停留信息。

## 入住分配

菜单：`入住分配`

用于办理人员入住、修改在住记录和办理退宿。

字段说明：

| 字段名 | 含义 | 是否必填 |
| --- | --- | --- |
| 人员 | 入住人员 | 是 |
| 宿舍 | 入住宿舍 | 是 |
| 房间 | 入住房间 | 是 |
| 入住日期 | 实际入住日期 | 是 |
| 预计退宿日期 | 预计退宿日期 | 否 |
| 备注 | 入住说明 | 否 |

辅助信息：

- 选择人员后，页面显示姓名、部门、性别、人员类型。
- 选择房间后，页面显示床位数、当前入住人数、性别限制。

如何办理入住：

1. 选择人员。
2. 选择宿舍。
3. 选择系统筛选出的可用房间。
4. 填写入住日期。
5. 可选填写预计退宿日期和备注。
6. 点击“新增入住记录”。

如何退宿：

1. 在入住列表中找到状态为“在住”的记录。
2. 点击“退房”。
3. 系统使用当天日期作为实际退宿日期，并将状态改为“已退宿”。

系统校验规则：

- 人员、宿舍、房间必须存在且未删除。
- 房间必须属于所选宿舍。
- 房间状态为 `disabled` 时不能入住。
- 人员性别必须符合房间性别限制。
- 房间当前入住人数不能超过床位数。
- 同一人员不能同时有多条 `active` 入住记录。
- 只有状态为 `active` 的入住记录允许修改和退宿。
- 已退宿记录不允许再次退宿。
- `active` 入住记录不能直接删除。
- 当前代码只允许删除 `cancelled` 或 `draft` 状态的入住记录；列表中的已退宿记录仍会被后端拒绝删除。

## 常见问题 FAQ

1. 无法登录怎么办？
   请确认用户名和密码是否正确。用户名不区分大小写，密码区分大小写。

2. 忘记密码怎么办？
   联系管理员在“用户管理”中重置密码。

3. 登录后刷新页面会退出吗？
   正常情况下不会，前端会根据本地 token 恢复登录状态。token 过期后需要重新登录。

4. 为什么看不到删除按钮？
   普通 `user` 角色不能删除数据，只有 `admin` 能看到删除按钮。

5. 为什么看不到字典、用户管理、系统菜单？
   这些菜单仅 admin 可见。

6. 无法新增入住怎么办？
   检查人员是否已有在住记录、房间是否满员、房间性别限制是否匹配、房间是否被禁用。

7. 为什么房间下拉没有可选房间？
   可能房间已满、房间性别限制不匹配、房间被禁用，或宿舍下没有可用房间。

8. 为什么人员不能删除？
   如果人员存在 `active` 入住记录，系统会阻止删除。请先办理退宿。

9. 为什么房间不能删除？
   如果房间存在 `active` 入住记录，系统会阻止删除。

10. 为什么宿舍不能删除？
    如果宿舍下属房间存在 `active` 入住记录，系统会阻止删除。

11. 风险颜色是什么意思？
    red 表示 30 天内到期或已超期，yellow 表示 31 到 60 天内到期，green 表示超过 60 天，未维护表示缺少最大停留日期或停留信息。

12. 人员英文名是否必填？
    不是。英文名为空时列表显示 `-`。

13. 部门为什么必须从下拉选择？
    部门来自字典 `departments`，用于统一统计和维护。

14. 人员已有旧部门但字典里没有怎么办？
    人员编辑时页面会保留当前值，并显示“当前值未在字典中”。

15. 车辆是否支持派车？
    当前不支持。车辆模块只维护基础档案、状态和到期日期。

16. 车辆状态如何停用？
    在车辆页面修改车辆，将状态改为 `disabled`。

17. 退宿时能选择退宿日期吗？
    当前页面点击“退房”后，系统使用当天日期作为退宿日期。

18. 已退宿记录能删除吗？
    当前后端只允许删除 `cancelled` 或 `draft` 状态的入住记录；已退宿记录不能直接删除。

19. 停留信息是否必须在新增人员时填写？
    不必须。可以先新增人员，再在人员页面或停留风险页面维护停留信息。

20. 字典修改后下拉不更新怎么办？
    字典修改后系统会触发刷新；如果仍未更新，请刷新浏览器页面。

21. 页面显示操作失败怎么办？
    当前页面通常会显示后端返回的中文错误，请根据提示处理；无法判断时联系管理员查看日志。

22. Dashboard 数据为什么和刚操作前不一样？
    成功新增、修改、删除或退宿后，相关列表会刷新；Dashboard 重新进入或刷新页面后会重新统计。
